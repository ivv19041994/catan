# Catan Engine

Игровой движок для базовой версии настольной игры «Колонизаторы» (Catan),
написанный на C++20. Он хранит состояние партии, проверяет допустимость ходов,
генерирует карту, рассчитывает ресурсы и очки, а также умеет рисовать карту и
состояние игрока в SVG. В репозитории есть экспериментальная консольная
оболочка, но основной полезный интерфейс проекта — класс
`ivv::catan::GameController`.

> Важно: это не законченная пользовательская игра. Ниже отдельно перечислены
> отличия текущей реализации от правил настольной Catan и ограничения консоли.

## Возможности

- Партия на 2–4 игроков; порядок игроков случайно перемешивается.
- Стандартное поле из 19 гексов, 54 перекрёстков и 72 рёбер.
- Случайное размещение 4 лесов, 4 пастбищ, 4 полей, 3 холмов, 3 гор и пустыни.
- Бросок двух кубиков, выдача ресурсов, разбойник и сброс карт при выпадении 7.
- Строительство поселений, городов и дорог; проверка соседства и расстояния
  между поселениями.
- Торговля с банком и через порты, сделки между игроками.
- Карты развития, самая длинная дорога, самая большая армия и победа при
  10 очках.
- SVG-рендереры карты и карточки игрока. Пример готовой карты —
  [`map.png`](map.png).

## Быстрый старт

Проект собирается CMake 3.20+; требуется компилятор с поддержкой C++20:

```bash
cmake -S . -B build
cmake --build build --parallel
./build/catan
```

Цели CMake:

- `catan_engine` — библиотека игровой логики;
- `catan_render` — библиотека SVG-рендеринга, зависящая от `catan_engine`;
- `catan` — экспериментальное консольное приложение;
- `catan_engine_tests` — тесты игровой логики.

Можно отключить приложение или тесты опциями `-DCATAN_BUILD_CONSOLE=OFF` и
`-DCATAN_BUILD_TESTS=OFF` соответственно. Проверено компилятором Apple Clang.
Исходный код содержит несколько существующих предупреждений, в том числе из-за
комментариев в не-UTF-8 кодировке.

### Тесты

Тесты не требуют стороннего фреймворка и запускаются через CTest:

```bash
cmake -S . -B build -DCATAN_BUILD_CONSOLE=OFF
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

Покрываются `GameController` и его доменные зависимости: стартовая
расстановка и переходы фаз, генерация карты и действие порта, карты развития
игрока, а также броски кубиков. Консольный парсер и SVG-рендеринг намеренно не
входят в тестовый набор.

Исполняемый файл запускает прототип консоли. На macOS/Linux он пытается
записывать SVG в жёстко заданный Windows-путь `D:/Users/Vadim/...`, поэтому
визуальные файлы из `main` не появятся. Команда `Map` всё равно печатает SVG в
стандартный вывод. Для встраивания или создания собственной оболочки
используйте `GameController` напрямую.

## Модель проекта

```text
console::Play ──────────────> GameController
                                  │
           ┌──────────────────────┼───────────────────────┐
           ▼                      ▼                       ▼
          Map                  Player                  Dice
     19 Gex (гексы)      ресурсы, карты,          два случайных
     54 Node (вершины)   постройки, очки            шестигранника
     72 Facet (рёбра)         │
           │                  ▼
           └──────── Construction: Settlement / Castle / Road

MapRenderer и PlayerRanderer ──> SVG-документ
```

| Компонент | Ответственность |
| --- | --- |
| `GameController` | Оркестрация партии, очередь хода и проверка игровых фаз. |
| `Map` | Топология поля, генерация ресурсов/чисел, порты и размещение объектов. |
| `Gex` | Гекс с ресурсом, числом и возможным разбойником. |
| `Node` / `Facet` | Перекрёсток / ребро. На `Node` стоит здание, на `Facet` — дорога. |
| `Player` | Ресурсы, 5 поселений, 4 города, 15 дорог, карты и победные очки. |
| `console::Play` | Разбор текстовых команд для ручной отладки. |
| `MapRenderer`, `PlayerRanderer`, `svg` | Формирование SVG без сторонних библиотек. |

Исходники находятся в [`src`](src). Публичные объявления движка сосредоточены
в [`src/game_controller.hpp`](src/game_controller.hpp),
[`src/map.hpp`](src/map.hpp) и [`src/player.hpp`](src/player.hpp).

## Использование движка из C++

Создайте контроллер с уникальными именами. Он сам перемешает порядок и начнёт
фазу стартовой расстановки.

```cpp
#include "game_controller.hpp"

using ivv::catan::GameController;

GameController game({"Alice", "Bob", "Clara"});

// Всегда передавайте имя game.GetCurrentPlayer().
game.BuildSettlement(game.GetCurrentPlayer(), /* nodeId */ 9);
game.BuildRoad(game.GetCurrentPlayer(), /* facetId */ 19);

// После завершения всей стартовой расстановки:
game.Dice(game.GetCurrentPlayer());
// ... строить, торговать, использовать карты ...
game.Pass(game.GetCurrentPlayer());
```

Идентификаторы перекрёстков (`nodeId`) лежат в диапазоне `0..53`, рёбер
(`facetId`) — `0..71`, гексов (`gexId`) — `0..18`. Для упрощения разработки
расположение всех этих идентификаторов уже показано на готовой
[`map.png`](map.png). SVG-рендер полезен, когда нужна карта с её текущим
состоянием или с новой случайной генерацией:

```cpp
#include "map_rander.h"

ivv::catan::renderer::MapRenderer renderer(game.GetMap(), {40, 40}, 100);
renderer.Render(std::cout);
```

`MapRenderer::Render` выводит целый SVG-документ; перенаправьте поток в файл
`.svg` либо оберните его в подходящий HTTP-ответ.

### Очерёдность фаз

Контроллер не даёт пропускать фазы. Текущая фаза доступна через `PrintStep`.

```text
ForwardBuildingSettlement → ForwardBuildingRoad
  (для игроков по прямому порядку)
BackwardBuildingSettlement → BackwardBuildingRoad
  (для игроков в обратном порядке; второй посёлок даёт стартовые ресурсы)
DiceDrop → CommonPlay → Pass → DiceDrop
                     │
        выпадение 7: DropCards → BanditMove → CommonPlay
        «Строительство дорог»: RoadBuilding → CommonPlay
```

Во время `CommonPlay` активный игрок может строить, покупать/применять карты
развития, торговать и завершить ход. На каждой публичной операции контроллер
проверяет, что передано имя игрока, чей сейчас ход (исключение — сброс ресурсов
после 7, где игроки проходят по очереди).

## Правила, реализованные движком

### Ресурсы и постройки

Обозначения ресурсов в консоли и примерах: `w` — древесина (Wood), `c` — глина
(Clay), `h` — зерно (Hay), `s` — овца (Sheep), `r` — руда (Stone).

| Действие | Цена |
| --- | --- |
| Дорога | 1 древесина + 1 глина |
| Поселение | 1 древесина + 1 глина + 1 зерно + 1 овца |
| Город (`Castle` в коде) | 2 зерна + 3 руды |
| Карта развития | 1 зерно + 1 овца + 1 руда |

Поселение приносит одну единицу ресурса с соседнего гекса, город — две.
Поселения должны быть не соседними; новое обычное поселение требует своей
смежной дороги. Дорога должна примыкать к собственной дороге или зданию.

Порты снижают цену банковского обмена: общий порт — до 3:1 для всех ресурсов,
специализированный — до 2:1 для своего ресурса. Без порта цена 4:1.

### Разбойник и карты развития

При сумме кубиков `7` каждый игрок с 8 или более ресурсами сбрасывает ровно
половину (округление вниз). Затем текущий игрок переносит разбойника на гекс и
может указать игрока с постройкой на нём, у которого будет случайно похищен
один ресурс. Гекс с разбойником не производит ресурсы.

Колода содержит 25 карт: 14 рыцарей, по 2 «Строительство дорог», «Год изобилия»
и «Монополия», а также по одной из пяти победных карт. Непобедные карты,
купленные в этом ходу, становятся доступны только после его завершения.

- Рыцарь переносит разбойника; игрок с минимум 3 сыгранными рыцарями получает
  «Самую большую армию» (+2 очка), если лидирует без ничьей.
- «Строительство дорог» даёт до двух бесплатных дорог.
- «Год изобилия» добавляет два указанных ресурса.
- «Монополия» забирает у остальных игроков весь указанный ресурс.
- Пять победных карт дают по очку после применения.
- Дорога длиной не менее 5 даёт «Самую длинную дорогу» (+2 очка), если она
  единолично длиннее остальных. Чужое здание разрывает маршрут.

Побеждает первый игрок с 10 или более очками.

## Консольный прототип

В текущем `main` игроки фиксированы как `1` и `2`, а перед интерактивным
циклом создаётся демонстрационное состояние. Это отладочный интерфейс, а не
полноценное создание новой партии. Команды чувствительны к регистру и имеют
формат с пробелами:

| Команда | Назначение |
| --- | --- |
| `Step` | Показать игровую фазу и активного игрока. |
| `Player <имя>` | Показать ресурсы, свободные фигуры, карты и очки игрока. |
| `Map` | Напечатать SVG текущей карты в stdout. |
| `LastDice` | Показать значения последнего броска. |
| `Dice <игрок>` | Бросить кубики в фазе `DiceDrop`. |
| `Sett <игрок> <nodeId>` | Поставить поселение. |
| `Road <игрок> <facetId>` | Поставить дорогу. |
| `Castle <игрок> <nodeId>` | Улучшить своё поселение до города. |
| `Market <игрок> <отдать> <получить>` | Обменять ресурс с банком по текущей цене. |
| `Deal <игрок> <ресурс> <кол-во> ... / <ресурс> <кол-во> ...` | Предложить сделку текущим игроком или принять зеркальную сделку другим игроком. |
| `Drop <игрок> <ресурс> <кол-во> ...` | Сбросить ресурсы при выпадении 7. |
| `BanditMove <игрок> <gexId> [жертва]` | Передвинуть разбойника; жертва необязательна, если на гексе нет построек. |
| `BuyDevCard <игрок>` | Купить карту развития. |
| `Knights <игрок>` | Сыграть рыцаря. |
| `RoadBuilding <игрок>` | Сыграть «Строительство дорог». |
| `YearOfPlenty <игрок> <ресурс1> <ресурс2>` | Сыграть «Год изобилия». |
| `Monopoly <игрок> <ресурс>` | Сыграть «Монополию». |
| `WinCard <игрок>` | Применить имеющуюся победную карту. |
| `Pass <игрок>` | Завершить ход. |

Пример обмена: `Market 1 w c` — отдать древесину и получить глину. Пример
предложения: `Deal 1 w 1 h 1 / r 1`; принять его второму игроку нужно
зеркальной командой `Deal 2 r 1 / w 1 h 1`.

## Известные ограничения

Документация описывает фактическое поведение исходников на момент подготовки,
а не только канонические правила. Существенные расхождения и недоделки:

- Игрок создаётся со **100 единицами каждого ресурса**, а не с нулём. Это явно
  режим отладки и сильно меняет баланс партии.
- Консоль не спрашивает имена/число игроков и выполняет заранее записанную
  стартовую расстановку. Пути для автоматического экспорта SVG жёстко привязаны
  к Windows-машине автора.
- В проекте нет системы сборки, тестов, сохранения/загрузки партии, сетевой или
  графической оболочки.
- Стандартное правило «не больше одной карты развития за ход» применяется
  только к рыцарю и трём картам действия. Победные карты можно применить в тот
  же ход.
- Обмены игроков реализованы как одно активное предложение, принимаемое только
  точным зеркальным набором ресурсов; отменить предложение отдельной командой
  нельзя (оно сбрасывается в конце хода).
- После хода с `7` сброс ресурсов идёт в порядке массива игроков, а игрок на
  целевом гексе обязан быть явно назван, если там есть постройки.
- Генератор ресурсов использует дополнительные ограничения на соседство,
  которые не являются буквальным воспроизведением стандартного сценария Catan.

   регрессионными тестами.
4. Разделить библиотечную часть и CLI-исполняемый файл, добавить сериализацию
   состояния и понятный API наблюдения за картой.
